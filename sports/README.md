## `index.html`에 구글 Apps Script 주소가 박혀 있는 이유

**이건 유출이 아니다. 감출 수 없는 값이고, 감추는 대신 무력화한 것이다.**

브라우저가 네이버 API를 직접 부르면 CORS에 막힌다. 그래서 Apps Script를 중계로
둔다. 그런데 이 주소는 페이지와 함께 브라우저로 전달되므로, 저장소를 비공개로
돌리든 뭘 하든 소스 보기 한 번이면 드러난다. **클라이언트로 내려가는 값은 비밀이
될 수 없다.**

그래서 방어를 주소의 비밀성이 아니라 엔드포인트의 권한 범위에 둔다. Apps Script
쪽에 허용 목록이 있어서, 네이버 스포츠 API 외의 주소는 거부한다.

```javascript
var ALLOW = /^https:\/\/api-gw\.sports\.naver\.com\//;
```

이 한 줄이 없으면 이 스크립트는 아무 주소나 대신 요청해주는 공개 중계기가 되고,
그 요청은 전부 내 구글 계정 명의로 나간다. **허용 목록이 이 구조의 유일한 방어선이다.**

### 살아 있는지 확인하는 법

배포 URL 뒤에 붙여서 브라우저로 열어본다.

| 요청 | 정상 응답 |
|---|---|
| `?url=https://example.com` | `{"error":"not allowed"}` |
| `?url=https://api-gw.sports.naver.com/schedule/games?...` | JSON 데이터 |

첫 줄에서 example.com 내용이 나오면 방어가 뚫린 것이다. 대개 코드는 고쳤는데
새 버전을 배포하지 않은 경우다 — [배포 관리] → 편집 → 버전 **새 버전** → 배포.
(“새 배포”를 만들면 URL이 바뀌어 `index.html`도 고쳐야 한다.)

### 하면 안 되는 것

- 저장소를 비공개로 돌리기 — 노출은 그대로고, 무료 플랜이면 Pages가 내려간다
- Apps Script를 허용 목록 없이 재배포하기
- 허용 목록을 넓히기 (다른 API가 필요하면 패턴을 추가하되, 와일드카드는 금물)

## 알아둘 것

- 탭을 열어두면 경기 중 1분, 평소 5분 간격으로 자동 갱신한다. 갱신 1회당
  Apps Script 호출 2건(야구·축구). 무료 한도는 하루 2만 건.
- 구장 좌표는 `VENUES`에 직접 넣어뒀다. 신구장이 생기거나 이름이 바뀌면 여기를 고친다.
- 네이버 상세 응답의 구조를 확정하지 못해, 트리를 훑어 패턴을 찾는 방식으로 읽는다.
  한글 이름을 못 붙인 항목은 버리지 않고 회색 원본 키로 표시한다 — 조용히 사라지면
  잘못됐다는 걸 알 수 없기 때문이다.
