안녕하세요, 헬로데이터사이언스 나성호입니다.

지난 7회차에서 Python과 Colab이라는 도구를 준비했으니, 오늘은 드디어 실전입니다. 6회차에서 소개해드린 맞춤형 GPT 두 개, **Data Analysis Planner(DAP)**와 **Python Code Assistant(PCA)**를 활용해서 고객 이탈 데이터를 처음부터 끝까지 분석해보겠습니다.

## 실습 파일부터 받으세요

오늘 쓸 데이터는 `customer_churn.csv`라는 더미 고객 이탈 데이터입니다. 아래 GitHub 저장소에서 내려받으실 수 있습니다.

- 저장소: [github.com/HelloDataScience/python-using-gpt](https://github.com/HelloDataScience/python-using-gpt)
- 파일 바로 받기: [customer_churn.csv](https://raw.githubusercontent.com/HelloDataScience/python-using-gpt/main/customer_churn.csv)

고객ID, 성별, 나이, 가입채널, 요금제, 가입일, 가입경과월, 최근30일 로그인수, 월평균사용시간, 고객센터문의수, 최근3개월 결제실패, 이탈여부, 이탈일 — 이렇게 13개 열로 구성되어 있습니다.

## 전체 프로세스 먼저 보고 가겠습니다

오늘 실습의 전체 흐름은 이렇습니다.

1. `customer_churn.csv` 파일을 준비합니다.
2. **Data Analysis Planner**에 파일을 첨부하고, 데이터 분석 계획을 세우도록 요청해 **md(마크다운) 파일**로 다운로드합니다.
3. **Python Code Assistant**에 방금 받은 md 파일과 `customer_churn.csv` 파일을 **함께** 첨부하고 코드 작성을 요청합니다. 그러면 계획에 담긴 모든 단계를 한 번에 구현한 **ipynb 파일**을 통째로 받습니다.
4. 받은 ipynb 파일을 Colab에서 열고, 셀을 순서대로 실행합니다.
5. 에러가 나면 에러 메시지를 Python Code Assistant에 붙여넣어 수정된 코드를 받습니다.
6. 실행이 끝난 ipynb 파일을 다시 Python Code Assistant에 첨부하고, 분석 결과를 요약해달라고 요청합니다.

정리하면 "계획 세우는 GPT"에서 md 파일 하나를 받고, "코드 짜는 GPT"에 그 md와 데이터를 같이 넣어주면 노트북 전체가 완성되는 구조입니다. 예전에는 계획의 단계마다 일일이 복사해서 코드를 하나씩 받아야 했는데, 이제는 그 과정이 한 번의 요청으로 줄어들었습니다. 하나씩 따라가 보겠습니다.

## 1단계: 분석 계획을 md 파일로 받기

먼저 **Data Analysis Planner**에 `customer_churn.csv` 파일을 첨부하고, 자연어로 작성한 지시를 입력합니다. 예를 들면 이런 식입니다.

> 첨부한 데이터로 월별 고객 이탈률을 확인하고, 연령대와 가입 채널별 이탈률을 계산하는 교차분석이 필요해. 그리고 이탈률이 가장 높은 집단의 특징을 확인해야 해.

그러면 이 GPT가 데이터를 실제로 뜯어보고, 도메인에 맞는 분석 계획을 세워서 md 파일로 제공합니다. 다운로드한 md 파일을 열어보면, 이런 식의 내용이 담겨 있습니다.

> **데이터 점검 결과 요약**
> - 데이터 크기: 2,000행 × 13열
> - 결측값 개수: 이탈일(1,668개)
> - 주요 구조: 고객 식별자, 인구통계, 가입 채널, 요금제, 가입일, 이용 행동, 결제 실패, 이탈 여부, 이탈일로 구성된 고객 이탈 분석 데이터입니다.
> - 전처리 방향: 가입일과 이탈일을 날짜형으로 변환하고, 월별 이탈률 계산을 위해 이탈월을 생성해야 합니다.

이 계획은 여러 단계(0단계, 1단계, 2단계…)로 나뉘어 있고, 각 단계마다 '지시'와 '이유'가 함께 적혀 있습니다. 다만 이번엔 이 계획을 단계별로 하나씩 복사해서 넘길 필요가 없습니다.

## 2단계: md 파일 + 데이터를 한 번에 넘겨서 ipynb 통째로 받기

이제 **Python Code Assistant**에 방금 받은 md 계획 파일과 `customer_churn.csv` 파일을 **동시에** 첨부하고 코드 작성을 요청합니다. 데이터 파일을 함께 첨부하면, AI가 실제 열 이름을 보고 코드를 짜기 때문에 존재하지 않는 컬럼명을 코드에 넣는 실수를 피할 수 있습니다.

잠시 후 계획에 담긴 모든 단계(구글 드라이브 마운트, 데이터 불러오기, 전처리, 월별 이탈률 계산, 교차분석까지)를 담은 ipynb 파일 하나를 통째로 받게 됩니다. 이 파일을 다운로드해서 Colab에서 열고, 셀을 위에서부터 순서대로 실행하면 됩니다(단축키: `shift + enter`).

## 코드를 실행했는데 문제가 생겼다면 — 에러와 버그

생성형 AI가 작성한 Python 코드를 실행하다 보면 문제가 생길 수 있습니다. 이때 '에러'와 '버그'를 구분하는 게 중요합니다.

|<center>구분</center>|<center>의미</center>|<center>생성형 AI 활용 시 주요 발생 원인</center>|
|---|---|---|
| 에러 (실행 실패) | 코드가 실행되지 않고 중간에 멈추는 현상 | AI가 존재하지 않는 컬럼명을 코드에 넣거나, 최신 버전에서 제외된 예전 함수를 제안할 때 발생 |
| 버그 (논리 오류) | 코드가 실행되지만, 의도하지 않은 결과를 내는 현상 | AI가 도메인 맥락이나 비즈니스 로직을 오해하여 잘못된 수식을 적용하거나, 데이터 필터링 기준을 누락할 때 발생 |

에러가 발생하면 Python이 에러 메시지를 출력하기 때문에 비교적 쉽게 발견할 수 있습니다. 하지만 버그는 코드가 정상적으로 실행되기 때문에, 결과를 꼼꼼히 검토하지 않으면 발견하기 어렵습니다. 3회차에서 말씀드렸던 것처럼, **생성형 AI가 작성한 코드가 실행되었다고 해서 분석 결과까지 정확하다고 할 수는 없습니다.** 사용자가 데이터 구조, 계산식, 행 개수 및 결과 범위 등을 직접 확인해야 합니다.

## 에러가 나면 이렇게 해결합니다

코드 실행 중 에러가 발생하면, 방법은 간단합니다. 맨 아래에 출력된 에러 메시지를 통째로 복사해서, Python Code Assistant에 붙여넣고 해결 방법을 요청하면 됩니다. Python Code Assistant는 구글 드라이브에 어떤 폴더가 있는지 알 수 없기 때문에, 에러 메시지를 그대로 알려줘야 정확한 해결책을 받을 수 있습니다. 예를 들어 `FileNotFoundError: [Errno 2] No such file or directory: '/content/drive/MyDrive/data'` 같은 에러 메시지를 붙여넣으면, "현재 구글 드라이브에 저장한 실습 데이터가 있는 폴더 경로로 변경해서 사용하세요"라는 식으로 원인과 해결책을 알려줍니다.

실제 강의에서 이 방식으로 함께 해결했던 에러 사례를 두 가지만 더 소개해드리겠습니다.

**사례 1. 한글 CSV 파일의 인코딩 에러**

`pd.read_csv()`로 한글이 포함된 CSV 파일을 불러올 때 `UnicodeDecodeError`가 나는 경우가 자주 있습니다. 파일을 저장한 프로그램(엑셀 등)이 `cp949`나 `euc-kr` 같은 한글 인코딩으로 저장했는데, `pandas`는 기본값으로 `utf-8`을 기대하기 때문에 생기는 문제입니다. 이 에러 메시지를 그대로 Python Code Assistant에 붙여넣으면, `pd.read_csv(path, encoding='cp949')`처럼 인코딩을 지정해서 다시 시도해보라고 안내해줍니다. 그래도 안 되면 `encoding='euc-kr'`로 한 번 더 시도해보시면 됩니다.

**사례 2. `skiprows`를 써야 하는데 AI가 `header`를 쓰는 경우**

파일 맨 위에 제목이나 안내 문구가 몇 줄 들어가 있어서, 실제 표는 3번째 줄부터 시작하는 CSV를 종종 만나실 겁니다. 이럴 때 필요한 건 앞의 n줄을 건너뛰는 `skiprows` 옵션인데, 프롬프트에 상황을 충분히 설명하지 않으면 AI가 종종 `pd.read_csv(path, header=2)`처럼 `header` 매개변수를 대신 씁니다. `header`는 "몇 번째 줄을 열 이름으로 쓸지" 지정하는 옵션이라 얼핏 비슷해 보이지만, 그 위에 있던 줄들이 그냥 통째로 사라지는 게 아니라 각기 다르게 취급되면서 열 이름이 이상하게 깨지거나 행이 밀리는 결과가 나옵니다. 이럴 땐 "파일 맨 위 n줄은 표가 아니라 안내 문구이니 건너뛰고 읽어야 해"라고 구체적으로 알려주시면, AI가 `skiprows=n`으로 정확하게 고쳐줍니다.

두 사례 모두 공통점이 있습니다. 에러 메시지나 파일 구조를 말로 정확하게 설명할수록, AI가 원인을 훨씬 빨리 찾아낸다는 것입니다.

## 분석이 끝나면 결과를 요약해달라고 하세요

모든 셀을 다 실행하고 나면, Colab 파일을 저장하고 구글 드라이브에서 다운로드합니다. 그리고 완성된 ipynb 파일을 다시 Python Code Assistant에 첨부하고, "분석 결과를 요약해줘"라고 요청합니다.

강의 자료에 있던 실제 요약 예시를 하나 보여드리면 이런 식입니다.

> 첨부한 노트북의 코드와 실행 결과를 확인해 분석 흐름, 주요 결과, 시각화에서 드러난 내용을 검토해 요약해드립니다.
>
> **분석 요약** — 전체 고객은 2,000명, 이 중 고객 332명이 전체 이탈률은 16.6%입니다. 전체 고객 모두 이탈일이 있고, 유지 중인 고객은 이탈일이 없어 데이터 정합성 문제는 없어 보입니다.
>
> 월별 이탈률은 2026년부터 상승세가 두드러집니다. 이 원인으로 신규 고객 유입이 4.02%로 가장 크고, 신규 이탈은 3.47%로 두 번째로 큰 영향을 줍니다.
>
> 세그먼트 문제에서는 20대 + 제휴이벤트 가입경로가 가장 취약한 집단입니다. 이 집단의 이탈률이 40.86%입니다.

이렇게 코드 실행 결과가 ipynb 파일에 저장되어 있으면, GPT가 그 출력 결과를 읽고 사람이 이해하기 쉬운 문장으로 요약해줍니다.

## 오늘 이야기 정리

오늘은 Data Analysis Planner로 계획(md)을 세우고, Python Code Assistant에 계획과 데이터를 함께 넘겨 노트북(ipynb) 전체를 한 번에 받고, 에러가 나면 해결하고, 마지막엔 결과까지 요약받는 전체 사이클을 실습해봤습니다. 이 흐름 하나만 익히시면, 어떤 데이터를 가져와도 같은 방식으로 분석하실 수 있습니다.

다음 9회차, 이 시리즈의 마지막 회차에서는 지금까지 배운 걸 총동원해서 반도체 품질 데이터로 좀 더 실전에 가까운 실습을 해보겠습니다. 이번엔 데이터를 분석하는 것에서 한 걸음 더 나아가, 보고서 양식의 빈칸을 자동으로 채우는 것까지 완성해보겠습니다. 감사합니다.
